# Screenme architecture

Native macOS menu bar app (Swift, AppKit + SwiftUI, macOS 15+). No dependencies. Project generated by XcodeGen from `project.yml`; every `.swift` file under `Sources/Screenme` and `Sources/ReportFormat` is compiled into the app.

`Sources/ScreenmeCLI` is the `screenme` command line tool and MCP server, embedded in `Contents/Helpers`. Whatever needs the app (captures, recordings, reports from a video, text recognition, redaction, History search, uploads, settings, the window list, Quick Access actions) it asks over the agent socket (`AppChannel`, starting the app in the background when nothing answers); captures, reports and `latest` it reads from disk itself. Every command is a `Command`, parsed from the command line or mapped from an MCP tool call (`Tool`, with typed arguments), and `Command.run(_:)` returns an `Output`, the text and the images it is about: `main` prints the text, `MCPServer` returns the images as pictures, then the text. For Reports for AI it reads the newest `Report …` folder in the save folder (`ReportLayout.latest(in:)`) through the report's `report.json` (`ReportBundle`; a report of an older version is not read, the error asks for Report for AI again): `zoom`, `frames` and `inspect`, and the MCP tools `get_latest_report`, `zoom_report` and `inspect_report`. `screenme skill` prints `skills/screenme/SKILL.md`, which the app carries in `Contents/Resources`. Its tests (`Tests/ScreenmeCLITests`) compile its sources directly, without the app.

`Sources/ReportFormat` is the code the app and the tool share, compiled into both (and into the tool's test target): the report's files and their names (`ReportLayout`, and `ScreenmePaths`, the app's defaults domain and the Captures and save folders), `report.json` (`ReportManifest`, version 2: the environment as typed fields, the date in ISO 8601), the recorded events (`RecordingEvent`, a time and a typed `Action`, written as the flat JSON objects events have always had), the contact sheet (`ContactSheet`, also the `zoom` grid), `Duration.format(_:tenths:)` and the bitmap helpers (`ImageDrawing`). Nothing in it knows about AppKit windows, the app's state or the tool's transport.

`Sources/AgentProtocol` is the agent socket's wire format, compiled into the app and the tool: `AgentChannel` (the socket at `~/Library/Application Support/Screenme/agent.sock`; one JSON request `{"command", "arguments"}` per connection, answered with `{"result"}` or `{"error"}`) and `AgentArguments` (arguments read by type; a wrong type is an error, never a default). In the app, `Core/Agent/` answers it: `AgentServer` listens (mode 0600, started by the app delegate except under tests), `AgentAPI` runs each command through the same code the menus use (`CaptureCoordinator.agentScreenshot`/`agentStartRecording`/`agentStopRecording`, `AIReporter.create`, `S3Upload.share`, `CaptureAction.perform`), and `AgentSetting.all` lists every Settings window preference with its kind and allowed values, written to `Prefs.store` so the app reacts as it does to the Settings window (the upload secret goes to the Keychain). A setting added to the Settings window gets a line in `AgentSetting.all`. The socket, not `screenme://` links, carries settings and uploads: a web page can open a link, it cannot reach a socket.

## Build

```bash
xcodegen generate
xcodebuild -project Screenme.xcodeproj -scheme Screenme -configuration Debug -derivedDataPath build/DerivedData build
```

Swift 5 language mode on the Swift 6 compiler. All UI types are `@MainActor`. AppKit windows must be created on the main thread.

## Rules

- A module edits only its own folder, plus Core when it extends the shared kit. Public signatures in the tables above change only together with every caller and this file.
- Need a new preference: `extension Pref { static let x = PrefKey(name: "x", defaultValue: …) }` in your own folder. Nothing is registered: `Prefs[Pref.x]` falls back to `defaultValue`, and every `@AppStorage(Pref.x.name)` must be initialized with `Pref.x.defaultValue`. A fixed set of choices is an enum with a `String` raw value, used as the pref's type.
- Every user action goes through `CaptureCoordinator.perform(_:target:)`; `target` comes from a `screenme://` link and replaces the picker. It runs one capture at a time (`busy` lasts until the file is delivered, GIF conversion included), never starts one while the All-in-One bar is open, and handles instant actions (All-in-One, Pin Last Capture, History, Hide Desktop Icons) before that gate. A capture shortcut or link while the bar is open goes to `AllInOneHUD.choose(_:target:)`, which closes the bar and hands the action and the link's target back to `perform`. The picker, scrolling capture and recording start rely on this and have no guards of their own.
- A new image capture goes through `CaptureCoordinator.shared.deliver(_:from:)`, which writes it and runs the after-capture actions; a stopped recording gets them in `stopRecording()`. A new file that opens somewhere on its own (a combined image) calls `record(item)` instead: last capture and History, without the after-capture actions. A file changed in place posts `.captureUpdated`.
- New captures go to `Storage.directory` via `Storage.write(_:)` or `Storage.newURL(extension:)`.
- Coordinates: `CaptureTarget.area` rects and `cocoaFrame` are global Cocoa coordinates (bottom-left origin). ScreenCaptureKit wants display-local, top-left. Convert global rects with `cocoaFlipped`.
- Screenme's own windows are excluded from every capture by `CaptureTarget.streamSetup`; pass windows that must be filmed (recording overlays) as `including:`.
- Overlay windows are `FloatingPanel`s; subclass only for a real override (key handling, `constrainFrameRect`). Taking focus goes through `FocusKeeper`, never a bare `NSApp.activate`.
- No em-dashes in UI copy.
