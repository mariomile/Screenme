# Screenme architecture

Native macOS menu bar app (Swift, AppKit + SwiftUI, macOS 15+). No dependencies. Project generated by XcodeGen from `project.yml`; every `.swift` file under `Sources/Screenme` is compiled.

`Sources/ScreenmeCLI` is the `screenme` command line tool and MCP server, embedded in `Contents/Helpers`. It shares no code with the app: it opens `screenme://` links (the app holds the Screen Recording permission) and reads `Storage.directory` for the new file. For Reports for AI it reads the newest `Report …` folder in the save folder, from the app's defaults domain `dev.mariomiletta.Screenme` (`saveDirectory`), through the report's `report.json` (`ReportBundle`, its own decoder of the fields it needs): `zoom`, `frames` and `inspect`, and the MCP tools `get_latest_report`, `zoom_report` and `inspect_report`. `screenme skill` prints `skills/screenme/SKILL.md`, which the app carries in `Contents/Resources`. Its tests (`Tests/ScreenmeCLITests`) compile its sources directly, without the app.

## Build

```bash
xcodegen generate
xcodebuild -project Screenme.xcodeproj -scheme Screenme -configuration Debug -derivedDataPath build/DerivedData build
```

Swift 5 language mode on the Swift 6 compiler. All UI types are `@MainActor`. AppKit windows must be created on the main thread.

## Shared kit in Core

Use these instead of writing your own. If one does not fit, extend it in Core rather than copying it.

|---------|-------|-------------------|
| A capture | `Core/CaptureItem.swift` | `CaptureItem` with `Kind` `.image`, `.video`, `.gif`. Switch on the kind; never test the file extension. `Notification.Name.captureUpdated` (object: the file URL) when a file changes on disk. |
| Capture actions | `Core/CaptureActions.swift` | `CaptureAction` (13 cases: copy, copyForAI, reportForAI, copyMarkdown, copyPath, save, saveAs, reveal, share, uploadLink, edit, pin, trash): `title(for:)`, `symbol(for:)`, `isAvailable(for:)`, `perform(_:) async`, and `confirm(savedTo:)`, the one toast per action. | Files | `Core/Capturer.swift` | `Storage.write(_:)`, `write(_:to:)` (safe off the main thread), `newURL(extension:)`, `save(_:)`, `savedCopy(of:)`, `saveAs(_:suggestedName:) async throws -> URL?`, `chooseDestination(suggestedName:) async -> URL?`, `copy(_:to:)`; `Clipboard.copy(_ item:)` (image data plus file, GIF data plus file, each as one pasteboard item, or a video file). |
| Capture filter | `Core/CaptureTarget.swift` | `CaptureTarget.streamSetup(showsCursor:retina:including:hidingNotifications:)`, the only place that builds an `SCContentFilter` for Screenme's own content. `NSScreen.at(_:)`, `NSScreen.underMouse`, `CGRect.cocoaFlipped`. |

## Rules

- A module edits only its own folder, plus Core when it extends the shared kit. Public signatures in the tables above change only together with every caller and this file.
- Need a new preference: `extension Pref { static let x = PrefKey(name: "x", defaultValue: …) }` in your own folder. Nothing is registered: `Prefs[Pref.x]` falls back to `defaultValue`, and every `@AppStorage(Pref.x.name)` must be initialized with `Pref.x.defaultValue`. A fixed set of choices is an enum with a `String` raw value, used as the pref's type.
- Every user action goes through `CaptureCoordinator.perform(_:target:)`; `target` comes from a `screenme://` link and replaces the picker. It runs one capture at a time (`busy` lasts until the file is delivered, GIF conversion included), never starts one while the All-in-One bar is open, and handles instant actions (All-in-One, Pin Last Capture, History, Hide Desktop Icons) before that gate. A capture shortcut or link while the bar is open goes to `AllInOneHUD.choose(_:target:)`, which closes the bar and hands the action and the link's target back to `perform`. The picker, scrolling capture and recording start rely on this and have no guards of their own.
- After a capture or an edit that produces a new file, call `CaptureCoordinator.shared.afterCapture(item)`. A new file that opens somewhere on its own (a combined image) calls `record(item)` instead: last capture and History, without the after-capture actions. A file changed in place posts `.captureUpdated`.
- New captures go to `Storage.directory` via `Storage.write(_:)` or `Storage.newURL(extension:)`.
- Coordinates: `CaptureTarget.area` rects and `cocoaFrame` are global Cocoa coordinates (bottom-left origin). ScreenCaptureKit wants display-local, top-left. Convert global rects with `cocoaFlipped`.
- Screenme's own windows are excluded from every capture by `CaptureTarget.streamSetup`; pass windows that must be filmed (recording overlays) as `including:`.
- Overlay windows are `FloatingPanel`s; subclass only for a real override (key handling, `constrainFrameRect`). Taking focus goes through `FocusKeeper`, never a bare `NSApp.activate`.
- No em-dashes in UI copy.
